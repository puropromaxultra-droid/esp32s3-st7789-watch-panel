# 连线表 · 照这个画原理图（**V5 · 电池 + 板载天线 + 按键 + 功放 + Flash**）

> 日期：2026-10-21 起，10-24 升到 **V5**　板框 **34 × 50 mm**
> 这块板一共 **33 个元件、31 个网络**。原理图阶段只有一件事：把这 31 个网络连对。
>
> ⚠️ **这一版和 V2 差很多**：加了充电/电池/两个板载按键，模组换回板载天线版。
> 如果你已经按 V2 画了一部分，请对照 §0 的变更表改，别两版混着画。
> **V3 → V5（10-24）**：新增 U4 功放 / U5 Flash / C8 C9 C11 / J7，元件 27 → 33、网络 22 → 31。
> 逐脚接法在 §3 的 U4 / U5 / J7 三段。

## 0. V2 → V3 变更表（先看这个）

| 项 | V2 | V3 | 为什么 |
|---|---|---|---|
| 板框 | 32 × 42 | **34 × 50** | 屏要让开天线区（+8 长），底部要放充电（+2 宽） |
| 模组 | MINI-1**U**-N8（IPEX 外置天线） | **MINI-1-N8**（板载天线） | 你不想接软天线；靠"板做大 + 屏让位"解决遮挡 |
| LDO 输入 | VBUS 5V | **VSYS**（USB 与电池二选一） | 有电池了 |
| 按键 | J3/J4 两个 2P 排针（外接） | **SW1/SW2 两个 6×6 轻触开关**（焊在板上，从外壳背面按） | 你要"按钮放后面" |
| 新增 | — | **U3 TP4056 + D1/Q2 + C6/C7 + R5/R6/R7/R8 + J5 + SW1/SW2** | 充电 + 电池 + 电量检测 + 按键 |
| 删除 | J3、J4 | — | 被 SW1/SW2 取代 |
| 网络 | 17 | **22**（+VSYS +BAT +ADC_BAT +CHRG +IO0） | |

**为什么又回到板载天线了**：V2 用 1U 是因为屏整块压在天线上。V3 把板加长 8mm、模组顶到板顶边缘，
屏顶边停在 **y=10.5**，模组本体 **y 0~20.5**、其中天线段 **y 0~5.4**，到屏还有 **5.1mm**，
屏的金属背板再也盖不到天线。
**前提：外壳在那个位置必须是塑料，不能有金属螺柱/卡扣/贴片。**

> ⚠️ **`MINI-1` 不是 15.4×15.4 那个方模块。** 带板载天线的 `MINI-1` 是 **15.4 × 20.5**，
> 比 `1U` 长 **5.1mm**（多出来那截就是天线）；`1U` 才是 15.4×15.4 的短款。
> 两者**焊盘完全相同**，但长度差 5.1mm，摆位必须按 **20.5** 算。
> 立创 `C2847294` 那颗是 **ESP32-S2**-MINI-1-N4 —— 另一个芯片、已停产、无库存，**不能拿来替**。

**为什么 LDO 换成 XC6220**：WiFi 峰值 355mA，V1 那个 200mA 的 XC6206 会掉压复位。
XC6220 是 **1A** 器件，dropout 只有 **60mV@300mA**（ME6211 是 100mV@200mA），静态电流 8µA（ME6211 是 40µA）。
**引脚和 ME6211 完全相同**（1=VIN 2=VSS 3=CE 4=NC 5=VOUT），原理图一根线都不用改，只换料号。

**为什么 D2 从肖特基换成 PMOS**：SS34 在 400mA 上有 0.3V 压降，电池 3.5V 时送到 LDO 只剩 3.2V。
AO3401 当理想二极管用，压降只有 `0.4A × 0.05Ω ≈ 0.02V` —— **这一颗比换 LDO 管用得多**。
两处一起改，电池能一路用到保护板截止，而不是 3.5V 就开始掉压重启。

**三个最容易连错的地方：**

1. **`VBUS` 和 `VSYS` 是两个网络，中间隔着 D1。** 原理图上的 `VBUS` 还同时接 U3 的 4 脚和 8 脚
   （充电输入 + 充电使能），别漏。
2. **`BAT` 和 `VSYS` 也是两个网络，中间隔着 Q2。** Q2 的**漏极(3) 接 BAT、源极(2) 接 VSYS**、
   栅极(1) 接 VBUS 并经 R8 10k 到 GND（电流只能从电池流出去，USB 的 5V 不能倒灌回电池 ——
   倒灌会绕过 TP4056 直接给锂电充电，危险）。
3. **`LCD_BL` 和 `LED_K` 不要合并**，中间隔着 Q1。

| 脚 | 信号 | 接 |
|---|---|---|
| 1, 2, 22 | GND | GND |
| 3–12 | DB0–DB7 + TE | **悬空**（SPI 模式不用） |

> **`MP` = Mounting Pin（固定脚）**，两个座子都有：J1 是 `MP`，J2 是 `SH ×4`。
> 它们**不传任何信号**，只负责机械固定 + 屏蔽，**全部接 GND**。
> 封装把固定脚拆成 MP1/MP2/MP3/MP4 时就**一个个都接 GND**；只接一个也行电气上，
> 但**焊接时必须每个都焊** —— 不焊固定脚，插拔几次就能把整个座子从板上撕下来。

### U2 · XC6220B331MR-G（SOT-23-5）

**引脚和 ME6211 一模一样，画原理图时不用改线，只把料号换掉。**

| 脚 | 名称 | 接 |
|---|---|---|
| 1 | VIN | **VSYS** |
| 2 | VSS | GND |
| 3 | CE | **VSYS**（**不能悬空**，B 型没有内部下拉） |
| 4 | NC | **悬空**（别接地，见下） |
| 5 | VOUT | +3V3 |

> ⚠️ 立创搜 `XC6220B331MR` 会出来**两个不同的东西**：
> - **C86534 / TOREX 原厂**：1A、dropout 60mV@300mA、**¥2.91 @1+**（500+ 才 ¥1.45）← **买这个**
> - C22466451 / TDSEMIC：只有 300mA、dropout **280mV**@100mA、¥0.55 ← **别买**，换上等于白改
>
> 原厂料号尾缀带 `-G`（无卤环保）。SOT-25 和 SOT-23-5 是同一个封装的两个叫法。

**可 pin-to-pin 替换的便宜料：`LW8233A23E` / 立创 `C47018755`（乐瓦微，¥0.80）。**
我核过它原厂手册（LW82XX Rev 1.1，22 页）的 PIN DESCRIPTION，SOT23-5L 是
**1=VIN 2=GND 3=EN 4=NC 5=VOUT**，和 XC6220 逐脚对齐 —— **符号和封装都不用改，焊哪颗都行**。

| | XC6220（C86534） | LW8233A23E（C47018755） |
|---|---|---|
| 输出电流 | 1A | 1A（限流 1.1~1.45A） |
| 压差 @300mA | 60mV | **95mV** |
| 压差 @500mA | ~100mV | **160mV** |
| 压差 @355mA（插值） | ≈70mV | **≈113mV** |
| 静态电流 | 8µA | 28µA |
| PSRR @1kHz | ≈70dB | 75dB |
| 输入上限 | 6V | 7V |
| 商城库存 | 24470 | **506**（贴装 2869） |
| 单价 @1+ | ¥2.91 | **¥0.80** |

按最坏情况（电池 3.2V、WiFi 发包 355mA）算：XC6220 → **+3V3 = 3.11V**；
LW8233 → **+3V3 = 3.07V**。ESP32 下限 3.0V，**两颗都过**，但 LW8233 只剩 67mV 余量，
电池可用下限从 3.09V 抬到 3.13V —— 容量上几乎没区别（锂电曲线尾部本来就陡）。

> **结论：第一版焊 XC6220。** 省 ¥2 不值得在"WiFi 到底稳不稳"上再叠一个未知品牌。
> 想省钱就两颗都买（LW8233 一颗才 ¥0.80），板子不用动。
>
> ⚠️ **4 脚必须悬空，别接地。** LW8233 手册写"NC 接地可改善散热"，但 XC6220 的 NC 脚
> 接地没有保证 —— 悬空是两种料都安全的接法。我们峰值损耗只有 `(3.7−3.3)×0.355 ≈ 0.14W`，
> SOT-23-5 的 θJA = 210℃/W，温升才 30℃，根本不需要靠 NC 脚散热。

### Q2 · AO3401（P 沟道 MOS，当理想二极管用）

**为什么不再用 D2**：SS34 在 400mA 上有 0.3V 压降，电池 3.5V 时送到 LDO 只剩 3.2V，

| 脚 | 名称 | 接 | 为什么 |
|---|---|---|---|
| **1** | **G 栅极** | **VBUS**，同时经 **R8 10k** 到 **GND** | USB 在 → 栅极 5V → **关断**；拔掉 → 被 R8 拉到 0V → **导通** |

> ⚠️ 这是 **P 沟道**，"源极接地"那套 NMOS 习惯在这里不适用。

### SW1 / SW2（轻触开关）

| 位号 | 组 A（两脚互通） | 组 B（两脚互通） |
|---|---|---|
| SW1（左） | **1、2 → GND** | **3、4 → BTN_A** |
| SW2（右） | **1、2 → GND** | **3、4 → BTN_B** |

**四个脚全用上**（10-21 定）。6×6 四脚开关内部是**同侧两脚本来就相通**，按下时两组才接通：

- 同侧那一对必须接**同一个网络**。接错（把一对拆开分到两个网络）就是永远导通，按键彻底失效。
- ★ **不要凭编号判断**：不同封装的 1/2/3/4 排法不一样。焊前用**万用表通断档量一遍**，
  内部通的那一对就是同侧 —— 按"对"分组，不看编号。
- 好处：4 个焊点抗疲劳（按键天天按，2 个焊点容易裂纹），单点虚焊还有冗余。
- GND 那一对直接落在铺铜里，**不用走线**；BTN 那一对相距 4.5mm，一根短线连起来即可
  （中间的 GND 铺铜会自动避让，DRC 会查）。
- 按下 = 信号被拉到 GND，固件开内部上拉，读到 LOW。
- ⚠️ **EDA 里的符号必须是 4 脚**（1、2 接 GND，3、4 接 BTN）。立创库里不少 `6x6 轻触`
  只给 **2 脚符号**（`SW_Push`），配上 4 脚封装后，多出来的两个焊盘**没有网络**，
  重导入变更时还会被清掉。选带 4 脚的符号，或在符号里把 1/2 并联、3/4 并联。
- ⚠️ **符号里 1–2 之间那条横线多半只是图形，不代表电气连通。** 原理图上要给 **1、2 各画一根线**
  接到 GND，**3、4 各画一根**接 BTN。验证方法：PCB 里逐个点这 4 个焊盘看网络属性，
  必须 4 个都有网络；只要有 2 个是空的，就是符号没连。

### J6 · IO0 下载救援点

| 脚 | 接 | 说明 |
|---|---|---|
| **1** | **`IO0`** | 下载模式检测脚 |
| **2** | **`GND`** | |

**它不是"多出来的东西"，是救砖唯一的手段。**

ESP32-S3-MINI-1 是 **LGA**，模组焊上以后 IO0 焊盘被压在底下、**完全看不到**。
哪天固件跑飞、USB 又认不出来，你没有别的办法把它拽回下载模式。

- **平时不焊针**，两脚悬着。模组内部 IO0 有上拉，正常启动。
- **救砖时**用镊子（或一根杜邦线）把 1、2 脚**短接**，再插 USB → 直接进下载模式。
- **不影响任何功能**：不短接就等于这个器件不存在。

> ⚠️ **J5 和 J6 都是 `1x02` 排针封装，别搞混。** J5 在板左侧（电池 `BAT`/`GND`），
> J6 在模组右侧（`IO0`/`GND`）。丝印要分别标 **`BAT`** 和 **`IO0`**，装完才分得清。

## 4. 电源怎么走（这一段理解错，板子会烧电池）

```
        J2 (USB 5V) ──┬─────────────► TP4056 VCC/CE ──► BAT ──┬──► J5 ──► 电池
                      │                     │                 │
                      │                     └── CHRG ──► IO2  ├──► R6/R7 ──► IO1（电量）
                      │                                       │
                      ├── D1(SS34, -0.30V) ──┐                │
                      │                     ├──► VSYS ─► XC6220 ─► +3V3
                      └── Q2(AO3401, -0.02V)┘                │
                                             ▲                │
                              BAT ───────────┘  体二极管只允许 BAT → VSYS
```

**三条走法：**

1. **插着 USB 时**：D1 导通（5 − 0.30 = 4.70V）；Q2 的栅极被 VBUS 抬到 5V，`Vgs = +0.35V` → **Q2 关断**。
   系统吃 USB 的电，电池只充电不放电。TP4056 同时给电池充。
2. **拔掉 USB 时**：D1 截止；Q2 栅极被 R8 拉到 0V，`Vgs ≈ -3.7V` → **Q2 导通**，压降只有 0.02V。
   Q2 的体二极管（BAT→VSYS）方向也一致，等于双保险。
3. **压差算清楚了，WiFi 满功率不用降档：**

| 电池电压 | VSYS（Q2 压降 0.02V） | +3V3（XC6220，dropout ≈0.07V@355mA） | 结论 |
|---|---|---|---|
| 4.20V（满） | 4.18V | 3.30V | ✓ |
| 3.70V（标称） | 3.68V | 3.30V | ✓ |
| 3.40V | 3.38V | 3.30V | ✓ 仍在稳压区 |
| **3.20V** | **3.18V** | **3.11V** | ✓ 高于 ESP32 的 3.0V，**WiFi 可以满功率发包** |
| 3.05V（快截止） | 3.03V | 2.96V | 该关机了 —— 但此时电池已经放到 95% |

对比改之前（ME6211 + SS34）：电池掉到 **3.5V** 就进压差区，等于 500mAh 只能用 400mAh。

> 现在**不需要**为了省电去降 WiFi 功率。`esp_wifi_set_max_tx_power(8)` 可以留作夜间延寿的可选优化，
> 但不再是"不降功率就会重启"的生存手段。

## 5. 四个"必须照抄"的地方（V2 的教训，一条都不能改）

**① J1 的 19 脚（IM）必须接 3V3。** 拉低 = 并口模式，初始化完全不生效，背光亮但全黑。

**② J2 的 CC1/CC2 各接一个 5.1k 下拉到地。** 少了电脑不给 5V。

**③ 背光是低边开关。** GPIO13 → Q1 栅极，Q1 源极接地，漏极接屏 LED−，屏 LED+ 接 3V3。
反了会烧 GPIO。

**④ U2 的 CE（3 脚）必须接 VSYS，不能悬空。** XC6220 的 B 型**没有内部下拉**，悬空时状态不确定
（可能关断，量不到 3.3V）。

## 6. "看着该连、其实不连"的地方

- DB0–DB7 / TE（J1 的 3–12 脚）全部悬空。
- SBU1/SBU2（A8/B8）悬空。
- **TP4056 的 STDBY（6 脚）悬空** —— 只用 CHRG 一个状态就够。
- **TP4056 的 TEMP（1 脚）接 GND，不是悬空** —— 悬空会被当成"电池过热"而拒绝充电。
